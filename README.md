# Генерация геологической карты

Минимальный прототип создаёт синтетическую истинную геологическую карту и автономный HTML-просмотрщик. Внешние Python-библиотеки не требуются.

## Структура проекта

```text
MapGenerationAndResourseRecognition/
├── config/             # настройки генерации и справочники
│   ├── generation.json
│   ├── minerals.json
│   └── rocks.json
├── src/geo_map/        # генератор и HTML-просмотрщик
├── tests/              # автоматические тесты
├── output/map/         # сгенерированные результаты
├── main.py             # точка запуска
└── README.md
```

## Запуск

```bash
.venv/bin/python main.py
```

После выполнения появятся:

- `output/map/map.json` - интервальное представление карты;
- `output/map/map_view.html` - интерактивный просмотрщик, работающий офлайн.

Откройте `map_view.html` в браузере. В нём доступны:

- вращаемая трёхмерная блочная модель;
- разрез по оси X в плоскости Y–Z;
- разрез по оси Y в плоскости X–Z;
- разрез по оси Z в горизонтальной плоскости X–Y;
- выбор координат на разрезах с шагом 1 м;
- включение и скрытие отдельных пород;
- отображение разных месторождений;
- просмотр характеристик выбранной ячейки.

## Настройка

Конфигурация разделена на три файла:

- `config/rocks.json` — только справочник пород: названия, цвета и диапазоны физических признаков;
- `config/minerals.json` — виды полезных ископаемых, цвета, веса появления и диапазоны параметров месторождений;
- `config/generation.json` — размеры карты и ограничения случайной генерации.

При запуске программа случайно выбирает по `seed`:

- количество, последовательность и толщину геологических слоёв;
- форму границ между слоями;
- количество месторождений;
- разные виды ископаемых без повторений в пределах одной карты;
- координаты центра и размеры каждого месторождения;
- максимальную концентрацию полезного ископаемого.

### Стратиграфические ограничения

В `config/generation.json` породы разделены на группы, перечисленные от поверхности к глубине:

1. верхние осадочные породы;
2. средние скальные и вулканические породы;
3. глубинные породы.

Генератор случайно выбирает породы внутри групп, но никогда не меняет порядок самих групп. Поэтому глубинный сланец, чёрный вулканит или обсидиан не могут оказаться выше осадочных пород. Поле `minimum_layers` задаёт, сколько представителей группы обязательно должно присутствовать на карте.

### Ограничения глубины месторождений

В `config/minerals.json` для каждого ископаемого задано поле `allowed_depth_m`. Оно определяет допустимый интервал залегания всего месторождения. Генератор размещает центр с учётом вертикального радиуса, поэтому месторождение целиком остаётся внутри заданных границ. Например, алмазоносное тело не может подняться выше 120 м, а угольный пласт ограничен интервалом 10–160 м.

### Форма месторождений

Месторождение строится как связное объёмное тело внутри базового эллипсоида. Плавный пространственный шум деформирует его горизонтальную границу, верхнюю и нижнюю поверхности, а также распределение концентрации. Для каждого тела случайно выбираются поворот, степень неровности и масштаб деформаций. Базовый эллипсоид используется только как ограничивающий объём, поэтому хаотичная форма не выходит за допустимый диапазон глубины.

В `config/generation.json` задаются не готовые слои и месторождения, а общие ограничения. Генератор выбирает вид ископаемого из `config/minerals.json`, после чего случайно создаёт месторождение по указанным для него диапазонам. Вручную указывать координаты месторождения не требуется.

При обычном запуске программа каждый раз выбирает новый случайный `seed`, поэтому создаётся новая карта. Использованное значение сохраняется в `map.json` и выводится в консоль.

Чтобы повторно создать конкретную карту, передайте сохранённый `seed` явно:

```bash
.venv/bin/python main.py --seed 100
```

При необходимости можно передать другие файлы конфигурации:

```bash
.venv/bin/python main.py --config config/generation.json --rocks config/rocks.json --minerals config/minerals.json
```

## Модель хранения

Карта сохраняется как набор постоянных горизонтальных ячеек. Внутри каждой ячейки находятся вертикальные интервалы пород и отдельные интервалы минерализации. Расчётные чанки в JSON не сохраняются.

Воксельная сетка используется только как логическое представление для срезов и визуализации.
