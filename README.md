# Генерация геологической карты

Прототип создаёт синтетическую **скрытую истинную геологическую карту**, моделирует разведочную экспедицию и по её наблюдениям восстанавливает объёмную геологическую модель и выделяет рудные зоны. Результат можно посмотреть в автономном HTML-просмотрщике. Внешние Python-библиотеки не требуются.

## Структура проекта

```text
MapGenerationAndResourseRecognition/
├── config/             # настройки генерации и справочники
│   ├── generation.json
│   ├── minerals.json
│   ├── observations.json
│   └── rocks.json
├── src/geo_map/        # генератор и HTML-просмотрщик
├── tests/              # автоматические тесты
├── output/map/         # сгенерированные результаты
├── main.py             # генерация, экспедиция и поиск
├── recognize.py        # поиск по существующей выгрузке
└── README.md
```

## Запуск

```bash
.venv/bin/python main.py
```

После выполнения появятся:

- `output/map/map.json` - интервальное представление карты;
- `output/map/map_view.html` - интерактивный просмотрщик, работающий офлайн.
- `output/map/observations/observations.json` — полный набор наблюдений экспедиции;
- `output/map/observations/tables/` — сводные CSV и GeoJSON по видам наблюдений;
- `output/map/observations/borehole_sources.json` — перечень двух самостоятельных источников бурения;
- `output/map/observations/sources/vertical_boreholes/` — JSON и семь CSV только вертикальных скважин;
- `output/map/observations/sources/inclined_boreholes/` — JSON и семь CSV только наклонных скважин;
- `output/map/observations/objects/index.json` — указатель отдельных файлов скважин, траншей, проб и структурных наблюдений;
- `output/map/recognition.json` — выделенные интервалы, аномалии, признаки по каждой цели и восстановленная карта;
- `output/map/reconstructed_map.json` — самостоятельная трёхмерная модель пород, рельефа, геофизических полей и рудных зон, построенная только по наблюдениям;
- `output/map/internal/expedition_run.json` — служебные параметры воспроизведения, не предназначенные для распознавания.

Откройте `map_view.html` в браузере. В нём шесть вкладок:

1. **Истинная карта** — геологическая модель и отдельные карты магнитной аномалии и гамма-фона.
2. **Предварительные наблюдения** — магнитное поле и гамма-фон, высоты, уклоны, типы рельефа и выходы пород на поверхность. Нажмите «Собрать наблюдения», чтобы выполнить съёмку по текущей карте прямо в браузере. В отчёте экспедиции используется тот же план съёмки, поэтому геофизические точки совпадают с данными, по которым выбраны места бурения.
3. **Разведочная экспедиция** — план бурения, журналы скважин, почвенные и канавные пробы, траншеи, структуры и лабораторный контроль качества. Здесь же можно скачать общий JSON с данными обоих этапов.
4. **Распознанная карта** — самостоятельная объёмная модель, разрезы X–Y, X–Z и Y–Z, рельеф, магнитное поле и гамма-фон. Доступны фильтры пород, рудных зон и обеспеченности данными, а также исходные наблюдения, поддерживающие цели.
5. **Найденные ископаемые** — оценка объёма, массы минерализованной породы и массы полезного компонента по каждому виду ископаемого, а также каталог пространственных рудных зон с содержанием, координатами, источниками и переходом к выбранной зоне на разрезе. Почвенные и геофизические аномалии показаны отдельно.
6. **Оценка сходства** — заглушка для сравнения результата распознавания с истинной картой.

Во вкладке истинной карты доступны:

- вращаемая трёхмерная блочная модель;
- план «Рельеф и обнажения» с высотами и породой в выбранной точке;
- разрез по оси X в плоскости Y–Z;
- разрез по оси Y в плоскости X–Z;
- разрез по оси Z в горизонтальной плоскости X–Y;
- выбор координат на разрезах с шагом 1 м;
- включение и скрытие отдельных пород;
- отображение разных месторождений;
- просмотр характеристик выбранной ячейки, породы-носителя, типа геологического контроля и содержания полезного компонента.

## Настройка

Конфигурация разделена на четыре файла:

- `config/rocks.json` — справочник пород: названия, цвета и диапазоны физических признаков;
- `config/minerals.json` — типы месторождений, единицы содержания, геологические модели и диапазоны размеров;
- `config/generation.json` — размеры карты и ограничения случайной генерации.
- `config/observations.json` — план бурения, список анализов и погрешности экспедиции.

По умолчанию карта имеет размер **1000 × 1000 × 500 м**: 100 × 100 горизонтальных ячеек размером 10 × 10 м и 50 шагов глубины по 10 м. Размеры в метрах вычисляются как `width_cells × cell_size_m`, `height_cells × cell_size_m` и `depth_cells × depth_step_m`. В просмотрщике координаты разрезов по-прежнему выбираются с шагом 1 м.

Сейчас справочник содержит 39 пород, включая 28 активных подземных пород, почву и специальные породы тел — кимберлит, пегматит и карбонатит. Справочник месторождений содержит 17 типов: медь, железо, золото, уголь, алмазы, изумруды, бокситы, уран, свинец–цинк, медь–никель, хромиты, олово–вольфрам, литий, вулканогенные медно-цинковые руды, фосфориты, марганец и редкоземельные руды.

При запуске программа случайно выбирает по `seed`:

- количество, последовательность и толщину геологических слоёв;
- форму границ между слоями;
- положение и смещение разломов;
- количество месторождений;
- только геологически допустимые виды месторождений без повторений в пределах одной карты;
- координаты центра и размеры каждого тела с учётом границ карты;
- максимальное содержание полезного компонента в единицах конкретного типа месторождения.

### Стратиграфические ограничения

В `config/generation.json` породы разделены на группы, перечисленные от поверхности к глубине:

1. осадочный чехол;
2. магматический и вулканический комплекс;
3. метаморфический фундамент.

Генератор случайно выбирает породы внутри групп, но не меняет порядок самих групп. Поле `minimum_layers` задаёт, сколько представителей группы обязательно должно присутствовать. Настройка `minimum_layer_thickness_m` соблюдается до формирования рельефа, а `surface_thickness_m` задаёт исходную толщину почвы. Специальные породы тел не входят в обычную стратиграфию и появляются только вместе с соответствующим месторождением.

### Рельеф и обнажения

Раздел `terrain` в `config/generation.json` задаёт диапазон высот `elevation_range_m` и характерный горизонтальный размер форм рельефа `feature_scale_m`. Высоты соседних ячеек меняются плавно и воспроизводятся по seed карты. По умолчанию высоты лежат между −55 и +85 м относительно условного нуля. На возвышенностях сохраняется почвенный покров. В понижениях он становится тоньше, а там, где поверхность срезает его целиком, видна верхняя из сохранившихся коренных пород.

В карте с рельефом отметка `surface_elevation_m` растёт вверх, а `from_depth_m` и `to_depth_m` отсчитываются вниз от общего нуля. Например, при высоте земли +25 м колонка начинается на глубине −25 м в шкале карты. Для скважины отсчёт начинается от её устья, а для почвенных и траншейных проб — от местной поверхности. Значение `terrain.enabled: false` строит плоскую поверхность.

По умолчанию экспедиция обследует 400 точек по сетке из раздела `outcrops` в `config/observations.json`. В `outcrop_observations` попадают точки, где видна коренная порода. Запись содержит наблюдённую породу, отметку и координаты с заданной погрешностью. Таблица и GeoJSON лежат в `observations/tables/outcrops/`, а отдельные записи — в `observations/objects/outcrops/`. Эти наблюдения доступны для будущих правил поиска. Почвенную пробу пропускают, если на заданной глубине нет нужного слоя почвы. Число таких пропусков хранится в `surface_unavailable_count`.

### Съёмка типов рельефа

Раздел `terrain_survey` в `config/observations.json` включает отдельную съёмку высот на сетке из 400 точек. Уклон рассчитывается по ближайшим измерениям вдоль X и Y. Для относительной высоты программа сравнивает точку со средними высотами симметричных пар соседей на расстоянии до двух шагов сетки. Поэтому классификация описывает форму рельефа вокруг точки на масштабе съёмки.

Уклон от 7° даёт класс «склон». При меньшем уклоне разница от +3 м означает «возвышенность», от −3 м вниз — «понижение». Остальные точки с малым уклоном считаются ровными. Если направление уклона оценить невозможно из-за отсутствия соседей, тип остаётся неопределённым. Количество точек, пороги и погрешность высоты настраиваются в `terrain_survey`.

Шаблон `templates/observations/terrain_observations.csv` совпадает по полям с выгрузкой `observations/tables/terrain/terrain_observations.csv`. В той же папке сохраняется GeoJSON для карты. Каждая точка также получает собственный JSON в `observations/objects/terrain/`. Карта и таблица с высотами, уклонами и типом рельефа доступны во вкладке «Предварительные наблюдения → Рельеф».

### Геологическая привязка месторождений

Каждый тип в `config/minerals.json` содержит `geological_model`. Поле `control` определяет, где разрешено формировать тело:

- `host` — только внутри заданных пород-хозяев;
- `stratiform` — пластовая или стратиформная минерализация, ограниченная подходящим слоем;
- `contact` — только возле реального контакта двух совместимых пород;
- `fault` — только в зоне влияния одного из сгенерированных разломов;
- `intrusive` — отдельное внедрённое тело замещает вмещающую породу; так создаются кимберлитовые трубки, пегматиты и карбонатиты.

Сначала создаются слои и разломы, затем генератор находит фактические допустимые ячейки и интервалы. Если нужной геологической обстановки на конкретной карте нет, этот тип не участвует в выборе. После построения геометрии минерализация ещё раз обрезается по разрешённым породам, контакту или зоне разлома. Поэтому наличие подходящей литологии теперь является реальным условием, а не декоративным признаком.

В `map.json` для проверки причинной связи сохраняются `geological_model`, `permitted_host_rock_ids`, `center_host_rock_id`, а для соответствующих моделей — `contact_depth_m`, `contact_pair_rock_ids`, `controlling_fault_id` или `country_host_rock_id`.

Связи пород и типов залежей заданы как упрощённые синтетические правила, а не как полноценный геодинамический симулятор. В качестве основы использованы общие классы моделей месторождений USGS, включая медно-порфировые и вулканогенные массивно-сульфидные системы: [Mineral Deposit Models](https://pubs.usgs.gov/bul/b1693/), [Porphyry Copper Deposit Model](https://pubs.usgs.gov/sir/2010/5070/b/), [VMS Deposit Model](https://pubs.usgs.gov/sir/2010/5070/c/).

### Ограничения глубины месторождений

В `config/minerals.json` для каждого типа задано поле `allowed_depth_m`. Оно определяет допустимый интервал залегания всего месторождения. Генератор размещает центр с учётом всех радиусов, поэтому ограничивающее тело остаётся внутри заданного диапазона глубин и горизонтальных границ карты.

### Форма месторождений

Месторождение строится как связное объёмное тело внутри базового эллипсоида. Плавный пространственный шум деформирует его горизонтальную границу, верхнюю и нижнюю поверхности, а также распределение содержания. Для каждого тела случайно выбираются поворот, степень неровности и масштаб деформаций. Это пока геометрическое приближение, после которого применяются реальные ограничения породы-хозяина, контакта, разлома или интрузивного тела.

### Содержание полезных компонентов

Схема не предполагает, что все значения выражены в процентах. В описании залежи используются универсальные поля `max_grade`, `grade_unit` и `display_threshold`, а в интервалах минерализации — `average_grade`, `maximum_grade` и `grade_unit`. Например, золото хранится в `g/t Au`, алмазы и изумруды — в `ct/t`, а медь — в `% Cu`.

В `config/generation.json` задаются не готовые слои и месторождения, а общие ограничения. Генератор выбирает вид ископаемого из `config/minerals.json`, после чего случайно создаёт месторождение по указанным для него диапазонам. Вручную указывать координаты месторождения не требуется.

При обычном запуске программа каждый раз выбирает новый случайный `seed`, поэтому создаётся новая карта. Использованное значение сохраняется в `map.json` и выводится в консоль.

Чтобы повторно создать конкретную карту, передайте сохранённый `seed` явно:

```bash
.venv/bin/python main.py --seed 100
```

При необходимости можно передать другие файлы конфигурации:

```bash
.venv/bin/python main.py --config config/generation.json --rocks config/rocks.json --minerals config/minerals.json
```

## Модель хранения

Карта с геофизикой сохраняется в схеме `2.2`. Схемы `2.1` с рельефом и `2.0` для плоской поверхности поддерживаются при загрузке. Внутри каждой ячейки находятся непрерывные вертикальные интервалы пород и отдельные интервалы минерализации. На верхнем уровне также сохраняются разломы и определения залежей. Расчётные чанки в JSON не сохраняются.

Воксельная сетка используется только как логическое представление для срезов и визуализации.

`map.json` — это ground truth. CSV и JSON экспедиции формируются как неполные и зашумлённые наблюдения. Будущие XLS/XLSX, Word и PDF должны использовать тот же набор наблюдений.

## Разведочная экспедиция

По умолчанию создаются 25 скважин длиной ствола 300 м с интервалом проб 5 м: девять вертикальных и шестнадцать наклонных под 60° к горизонту, направленных на восток или запад. Также создаются 100 точек почвенной геохимии, три траншеи длиной 300 м и глубиной 2 м, наблюдения пересечённых зон разломов и контрольные пробы. Панель из 17 скважинных и траншейных аналитов задаётся заранее и не зависит от того, какие залежи есть в карте. Для почв по умолчанию используются Cu, Fe и Au. Составные показатели, например `Pb+Zn`, сохраняются как составные: разделения на отдельные элементы нет. Параметры, коэффициенты переноса и пределы обнаружения — настройки синтетического эксперимента, а не характеристики реального лабораторного метода.

### Геофизическая съёмка

В истинной карте геофизические поля рассчитаны над каждой ячейкой. Справочник пород содержит объёмную магнитную восприимчивость в СИ, калий в процентах и эквивалентные уран и торий в ppm. Для основных пород взяты характерные уровни из опубликованных таблиц. Для пород без прямого аналога в таблицах использованы оценки по близким породам. В почве верхнего слоя концентрации U и Th наследуются от материнской породы, а доля K по умолчанию составляет 70% исходной. Это упрощённый сценарий выветривания. [Радиоэлементы в породах и почвах](https://crcleme.org.au/Pubs/OPEN%20FILE%20REPORTS/OFR%20144/07Radiometrics.pdf) · [Справочные диапазоны магнитной восприимчивости](https://www.eoas.ubc.ca/courses/eosc350/content/foundations/properties/magsuscept.htm)

`magnetic_anomaly_nt` считается для заданного регионального поля. По умолчанию оно составляет 50 000 нТл с наклонением 65°. Слои представлены эквивалентными цилиндрами с заданным радиусом. Вклад определяется восприимчивостью, мощностью и глубиной слоя под местной поверхностью. Результат сглаживается по горизонтали и центрируется относительно медианы участка. Для железорудного профиля дополнительная восприимчивость масштабируется по содержанию Fe относительно опорных 45%. Это приближение индуцированной намагниченности. Для наземной съёмки с учётом остаточных погрешностей принято стандартное отклонение 1 нТл. [Индуцированная намагниченность и аномалия полного поля](https://topex.ucsd.edu/pub/class/geodynamics/HW4_papers/A_magnetics.pdf) · [Пример наземной съёмки с базовой станцией](https://gq.mines.gouv.qc.ca/documents/examine/GM66520/GM66520.pdf)

`gamma_count_rate_cps` — сумма ожидаемых отсчётов в трёх энергетических окнах K, U и Th с добавлением настраиваемого фона прибора. Чувствительности 3,36, 0,586 и 0,265 имп/с на единицу концентрации получены суммированием строк таблицы 4.1 МАГАТЭ для детектора NaI(Tl) 76 × 76 мм. Экранирование рассчитывается по толщине и плотности верхних слоёв. Уран в руде вычисляется из содержания U₃O₈ по коэффициенту 8 480 ppm U на 1% U₃O₈. В полевых наблюдениях к погрешности прибора добавляется статистическая неопределённость счёта за 60 секунд. [Калибровка гамма-спектрометрии](https://www-pub.iaea.org/mtcd/publications/pdf/te_1363_web.pdf) · [Пересчёт массы U₃O₈ в уран](https://pubs.usgs.gov/of/2010/1001/pdf/OF10-1001.pdf)

Параметры полей находятся в `geophysics` в `config/generation.json`. Сохранённые карты читаются со своими полями. Чтобы пересчитать их по текущим справочникам и собрать новую экспедицию, используйте `main.py --map путь/к/map.json --recompute-geophysics --output путь/к/выгрузке`.

План `geophysical_survey` в `config/observations.json` по умолчанию включает 400 станций. У магнитных и гамма-измерений свои идентификаторы `MAG-*` и `GAM-*`, свои показания и погрешности. Записи с одной станции связывает `station_id`. CSV и GeoJSON магнитных наблюдений сохраняются в `observations/tables/geophysics/magnetic/`, гамма-наблюдений — в `observations/tables/geophysics/gamma/`. JSON отдельных замеров распределяются по тем же каналам внутри `observations/objects/geophysics/`. В «Предварительных наблюдениях» доступны отдельные разделы «Магнитное поле» и «Гамма-фон» со своими таблицами и кнопками скачивания.

План экспедиции и её погрешности задаются в `config/observations.json`. Интерфейс отображает уже сгенерированные данные; для изменения экспедиции нужно изменить конфигурацию и повторно запустить программу. Новую экспедицию можно создать на существующей истинной карте:

```bash
.venv/bin/python main.py --map output/map/map.json --observation-seed 200
```

Чтобы воспроизвести и карту, и экспедицию:

```bash
.venv/bin/python main.py --seed 100 --observation-seed 200
```

Без `--observation-seed` случайность экспедиции выбирается независимо от случайности карты. Для другой конфигурации используйте `--observations-config путь/к/настройкам.json`. Дата кампании задаётся полем `date` и сохраняется при повторном запуске.

В `drilling.layout` доступны смешанный план `hybrid`, регулярная сетка `grid`, случайное размещение `random` и ручной план `manual`. Скважины прямолинейные, вертикальные или наклонные. Общие `drilling.azimuth_deg` и `drilling.dip_deg` задают направление по умолчанию. Без этих полей сохраняется вертикальное бурение с азимутом 0° и углом −90°.

- `azimuth_deg` — азимут по часовой стрелке от севера (+Y): 0° — север, 90° — восток (+X), 180° — юг, 270° — запад; диапазон `[0, 360)`.
- `dip_deg` — угол от горизонтали вниз, в диапазоне `[-90, 0)`: -90° — вертикаль, -60° — наклонная скважина под 60° к горизонту.
- `depth_m`, экспортируемое `total_depth_m` и скважинные `from_m`, `to_m`, `depth_m` — **расстояния вдоль ствола от устья**, а не вертикальные глубины. Интервал проб тоже отсчитывается вдоль ствола.

Для длины `s` координаты точки ствола вычисляются как `x = x_устья + s × cos(dip) × sin(azimuth)`, `y = y_устья + s × cos(dip) × cos(azimuth)`, вертикальная глубина — `s × sin(|dip|)`. Например, при длине 300 м и угле -60° забой находится на глубине примерно 259,8 м с горизонтальным отклонением 150 м. Искривление ствола и ошибки измерения направления пока не моделируются; координатная погрешность устья согласованно смещает всю наблюдаемую траекторию.

Для автоматических планов список `drilling.orientations` циклически задаёт направления скважин. Текущая конфигурация чередует вертикальную, восточную наклонную и западную наклонную скважины. Для каждого направления устья размещаются в области, где весь ствол остаётся внутри карты.

По умолчанию действует `hybrid`. План резервирует `drilling.random_fraction` скважин для случайного покрытия участка. При 25 скважинах и доле 0,4 это 10 точек. Для оставшихся скважин планировщик использует координаты и показания наземной геофизической съёмки, выполненной до бурения. Он ищет отклонения магнитного поля в обе стороны и превышения гамма-фона. Порог по каждому каналу учитывает разброс показаний и погрешность прибора. Планировщик чередует каналы, когда кандидаты есть в обоих, и размещает несколько скважин в окрестностях выбранных точек. Если измерений недостаточно, аномалий нет или целевая траектория не помещается, соответствующие скважины получают случайные точки.

В `observations.json` поле `drilling_targets` связывает целевую скважину с каналом и идентификатором исходного наблюдения. На плане бурения в просмотрщике случайные точки показаны синим, магнитные — оранжевым, гамма-аномалии — фиолетовым.

Для ручного плана в `drilling.holes` указываются `hole_id`, `x_m`, `y_m` и необязательные `depth_m`, `azimuth_deg`, `dip_deg`, переопределяющие общие значения. Список `orientations` используется только в автоматических планах. Например:

```json
"drilling": {
  "layout": "manual",
  "depth_m": 300,
  "sample_length_m": 5,
  "holes": [
    {"hole_id": "BH-001", "x_m": 200, "y_m": 200},
    {"hole_id": "BH-002", "x_m": 400, "y_m": 200, "azimuth_deg": 90, "dip_deg": -60}
  ]
}
```

Устья и забои проверяются по фактическим размерам входной карты. Ручная траектория за пределами карты отклоняется, а не обрезается. Длина наклонного ствола может превышать вертикальную глубину модели, если весь ствол помещается в её объёме.

Литология и состав проб рассчитываются по всем пересечённым ячейкам и вертикальным интервалам. Деление выполняется на точных пересечениях с границами ячеек, пород и минерализации; содержание усредняется по массе вдоль всего интервала пробы. Пересечения зон разломов также определяются по наклонной траектории. В просмотрщике показаны проекции стволов на плане и траектория выбранной скважины в вертикальной плоскости с отдельной вертикальной глубиной. Журнал и график анализов сохраняют шкалу расстояния вдоль ствола.

### Раздельные источники бурения

Генератор формирует два самостоятельных источника наблюдений:

| Источник | Условие | Каталог |
| --- | --- | --- |
| Вертикальное бурение | `dip_deg = -90` | `observations/sources/vertical_boreholes/` |
| Наклонное бурение | `-90 < dip_deg < 0` | `observations/sources/inclined_boreholes/` |

В каждом каталоге есть самостоятельный `observations.json` и семь таблиц: `borehole_collars.csv`, `borehole_lithology.csv`, `borehole_assays.csv`, `downhole_properties.csv`, `structural_observations.csv`, `fault_intersections.csv`, `downhole_gamma.csv`. Пакеты содержат только свои скважины и связанные с ними записи. Они используют общую схему полей для последующего объединения; источник определяется по собственным `source_id` и `kind`, а записи связываются по `campaign_id` и `hole_id`. Самостоятельный JSON включает справочник наблюдённых пород, единицы, план и соглашения о глубине — исходная истинная карта для его чтения не требуется.

`borehole_sources.json` перечисляет источники, пути к каталогам, идентификаторы скважин и количества записей. Сводный `observations.json` содержит тот же перечень без повторного вложения всех таблиц. Лабораторный контроль кампании хранится в `tables/quality_control/quality_control.csv`.

В просмотрщике фильтр «Источник бурения» переключает скважины, их план и связанные таблицы. Кнопка «Скачать источник · JSON» выгружает полный выбранный источник, а «CSV источника» — все его записи текущей таблицы. При отсутствии скважин выбранного типа источник остаётся пустым; при повторной генерации его файлы тоже обновляются.

Два отдельных комплекта шаблонов с согласованными примерами находятся в `templates/observations/sources/vertical_boreholes/` и `templates/observations/sources/inclined_boreholes/`. Их перечень — `templates/observations/borehole_sources.json`. Примеры имеют разные идентификаторы `EXAMPLE-V-*` и `EXAMPLE-I-*`.

### Файлы отдельных объектов

При каждом запуске генератор создаёт отдельный JSON для каждой скважины, траншеи, физической пробы и структурного наблюдения. В `observations/objects/index.json` можно найти путь по типу объекта и его идентификатору. Все пути в указателе и в полях `sample_files` и `structural_files` отсчитываются от каталога `observations/objects/`.

| Объект | Пример пути от `observations/objects/` | Содержимое |
| --- | --- | --- |
| Вертикальная скважина | `vertical_boreholes/BH-001/BH-001.json` | Устье, параметры ствола, описание пород, ссылки на пробы и структурные наблюдения |
| Наклонная скважина | `inclined_boreholes/BH-002/BH-002.json` | Устье, параметры ствола, описание пород, ссылки на пробы и структурные наблюдения |
| Скважинная проба | `vertical_boreholes/BH-001/samples/BH-001-S0001.json` | Анализы всех компонентов, плотность и пористость для того же интервала |
| Траншея | `trenches/TR-001/TR-001.json` | Положение, размеры, описание материала у дна и ссылки на пробы |
| Траншейная проба | `trenches/TR-001/samples/TR-001-S0001.json` | Интервал вдоль траншеи и анализы пробы |
| Почвенная проба | `surface_geochemistry/SG-001.json` | Координаты, глубина отбора и анализы пробы |
| Контрольная проба | `quality_control/duplicates/QC-D-BH-001-S0020.json` | Результаты контроля. Холостые пробы лежат в `blanks/`, стандарты в `standards/` |
| Структурное наблюдение | `vertical_boreholes/BH-001/structures/BH-001-F001.json` | Описание контакта или зоны разлома. Для разлома здесь же хранится интервал пересечения |

Исходный идентификатор сохраняется внутри файла и в указателе даже при замене имени файла для совместимости с файловой системой. Отдельные файлы формируются для фактически полученных наблюдений. При повторной генерации каталог `objects/` обновляется целиком. Сводные таблицы и файлы отдельных объектов представляют одни и те же измерения.

### Скважинный гамма-каротаж

Наблюдение включается через `downhole_gamma.enabled` в конфигурации экспедиции. По умолчанию формируется отдельный журнал с интервалами по 1 м вдоль каждого вертикального или наклонного ствола. Сигнал в имп/с приближённо моделируется по локальному составу пересечённых пород на текущей шкале синтетической гамма-модели. Погрешность учитывает заданный шум и разброс счёта за установленное время. Обсадка и жидкость в скважине не моделируются. Потеря отдельной пробы керна не удаляет запись каротажа.

Сводный CSV находится в `observations/tables/boreholes/downhole_gamma.csv`. У каждой скважины собственный журнал JSON в подкаталоге `gamma_log/` внутри каталога объекта. В интерфейсе откройте «Разведочная экспедиция → Скважины». График показывает гамма-сигнал вдоль ствола, а таблица «Гамма-каротаж» — измерения и погрешности.

При распознавании аномалия каротажа в пределах уже выделенного по анализам уранового интервала используется как дополнительное свидетельство. Самостоятельная классификация минерала по суммарному сигналу не выполняется.

### Сводные таблицы и геометрия

Файлы в `observations/tables/` сгруппированы в папки `boreholes/` для всех скважин, `trenches/` для траншей и их геометрии, `surface_geochemistry/` для почвенных проб и `quality_control/` для лабораторного контроля.

- `borehole_collars.csv` — измеренные положения устьев и параметры скважин;
- `borehole_lithology.csv` — описания керна с неточностью границ и возможными ошибками определения пород;
- `borehole_assays.csv` — интервальные анализы, включая результаты ниже предела обнаружения;
- `downhole_properties.csv` — плотность и пористость на интервалах проб;
- `downhole_gamma.csv` — природный гамма-сигнал и его погрешность на интервалах вдоль скважины;
- `structural_observations.csv` — контакты пород и зоны разломов, наблюдённые в керне;
- `fault_intersections.csv` — интервалы нарушенных пород, связанные со структурными записями;
- `surface_geochemistry.csv` — результаты почвенного опробования;
- `trenches.csv` — положения, размеры и состояние траншей;
- `trench_intervals.csv` — описание материала у дна вдоль траншей;
- `trench_samples.csv` — канавные пробы и результаты их анализов;
- `quality_control.csv` — дубликаты, холостые пробы, стандарты и результаты QA/QC;
- `surface_geochemistry.geojson` — те же почвенные результаты с геометрией `Point`;
- `trench_paths.geojson` — те же положения траншей с геометрией `LineString`.

Содержание рассчитывается по всему интервалу пробы с учётом массы пересечённых пород. Интервалы проб задаются планом и не подстраиваются под границы минерализации. Потерянные пробы отсутствуют одновременно в анализах и физических измерениях; их количество указано в сводке. Координатная погрешность задаётся один раз на скважину, а связанные записи используют её `hole_id`. Погрешности задаются как стандартные отклонения; вероятность пропуска проб и ошибки определения породы — в диапазоне `[0, 1]`. Ограничение на объём одной кампании — миллион анализов.

`ideal: true` отключает ошибки, пропуски, лабораторное смещение, загрязнение и отсечение результатов по пределу обнаружения. Предел метода остаётся в метаданных, а сами результаты в этом режиме представляют идеальное опробование модели. В обычном режиме результат ниже предела записывается как значение предела и `result_qualifier=lt`. Это верхняя граница, а не измеренное содержание. Оценки QA/QC находятся в отдельной таблице; `qc_flag` первичных проб остаётся `not_checked`, потому что групповой лабораторный контроль не подтверждает каждый отдельный анализ.

### Поверхностная геохимия

Раздел `surface_geochemistry` включается через `enabled`. Доступны планы `grid`, `random`, `manual`. Для ручного плана в `points` задаются `sample_id`, `x_m`, `y_m`. Интервал отбора должен целиком находиться в породе `soil`.

Для каждого аналита отдельно задаются `background_grade`, `background_variation_fraction`, `background_scale_m`, `response_factor`, `depth_decay_m`, `lateral_spread_m`, единица и предел обнаружения. Сигнал сохранённых интервалов минерализации интегрируется с экспоненциальным ослаблением по глубине и усредняется по соседним колонкам с гауссовым весом. Радиус рассеивания не может быть меньше половины исходной ячейки. К сигналу добавляется плавный фон, затем применяется общая лабораторная модель.

Фон зависит от физического содержимого карты и параметров модели. Он не меняется при другом seed экспедиции, дате, переименовании залежей или перестановке колонок. Скрытые фоновые значения и коэффициенты переноса не экспортируются в пакет наблюдений. Для почв поддерживаются явно заданные модели Cu, Fe, Au, Mn и отдельных оксидных показателей. Coal, Diamond, Emerald, TREO и суммы элементов требуют отдельных моделей и отклоняются. Это условная синтетическая модель сигнала, не физический расчёт миграции вещества.

### Траншеи

Раздел `trenches` поддерживает `grid` и `manual`. В регулярном плане задаются `trench_count`, `length_m` и `azimuth_deg` (по часовой стрелке от севера). В ручном плане в `paths` задаются `trench_id`, `start_x_m`, `start_y_m`, `end_x_m`, `end_y_m`. Все траншеи прямые, с общими `depth_m`, `width_m`, `sample_length_m` и `sampling_height_m`.

Журнал описывает материал непосредственно над дном. Глубина траншеи отсчитывается от местной поверхности вдоль всей трассы. Проба представляет полосу высотой `sampling_height_m` у дна и заданной длиной вдоль оси траншеи. Расчёт делит её по пересечённым горизонтальным ячейкам и вертикальным интервалам и усредняет содержание по массе. Геометрия поперёк ширины не интегрируется. Одна координатная ошибка смещает оба конца траншеи согласованно. Двухметровая траншея вскрывает коренную породу там, где мощность покрова меньше глубины выработки.

### Структуры

`structures.enabled` включает структурные наблюдения; `observe_contacts` и `observe_faults` отдельно управляют контактами и зонами разломов. Генератор использует ту же геометрию зон разломов, что и истинная карта, и создаёт записи только при пересечении со скважиной. Вероятность обнаружения, ошибка глубины и углов задаются настройками. Старые конфигурации без раздела `structures` сохраняют прежние наблюдения контактов без наблюдений разломов.

При `method=oriented_core` записывается зашумлённая ориентация разлома. При `method=core_logging` поля ориентации пусты. Ориентация контактов и смещение не определяются. Трещины, жилы и сланцеватость не выдумываются: для них сначала нужны соответствующие скрытые структуры в истинной карте.

### Контроль качества

`quality_control.enabled` включает контрольные пробы. `duplicate_every`, `blank_every` и `standard_every` задают частоту по числу физических первичных проб всех методов; ноль отключает соответствующий контроль. Дополнительная серия добавляется в конце неполного интервала контроля. Для каждой контрольной пробы измеряется панель аналитов соответствующего источника.

Дубликат использует тот же скрытый состав физической пробы с независимой ошибкой подготовки и анализа. Его `parent_sample_id` ссылается на существующую первичную пробу. В таблице публикуется измеренное значение исходной пробы, а не истинное содержание. Для холостой пробы известно нулевое контрольное содержание, для стандарта — синтетическое сертифицированное значение (`standard_detection_limit_multiple × detection_limit`) с заданной неопределённостью.

Дубликаты оцениваются по относительной разности пары измерений, стандарты — по отклонению от контрольного значения, холостые пробы — по абсолютному допуску. До одного допуска — `pass`, до двух — `warning`, выше — `fail`. Цензурированные результаты дубликатов получают `not_checked`. Для стандарта ниже предела обнаружения возможен `fail`, если даже верхняя граница результата гарантированно выходит за допуск; точное отклонение при этом остаётся неизвестным.

`batch_bias_fraction` и `contamination_detection_limits` задают общее смещение и загрязнение лабораторных анализов, применяемые одинаково к полевым и контрольным пробам. Они действуют и при выключенной выдаче контрольных проб, позволяя сравнивать кампании с лабораторным контролем и без него. В публичные данные эти скрытые параметры не попадают. Лимит миллиона анализов учитывает все методы и верхнюю оценку объёма QA/QC.

### Допущения первой версии

Содержание скважинных и траншейных проб считается постоянным внутри сохранённого интервала минерализации. Вне таких интервалов принято нулевое содержание; слабая минерализация, отсечённая при построении карты, не восстанавливается. Поверхностная геохимия использует отдельный условный фон и модель переноса. Плотность и пористость берутся из истинных интервалов, затем добавляется погрешность измерения. Более короткая проба не добавляет пространственной детализации исходной модели. Шаблоны Word, PDF и Excel остаются образцами; генерация документов будет отдельным этапом.

### Разделение данных

`observations.json` и CSV содержат только поля наблюдений. В них нет seed, идентификаторов залежей, индексов ячеек, геометрии тел и готовых признаков наличия руды. Все графики и таблицы экспедиции строятся из этого публичного набора. Служебные seed и конфигурация воспроизведения находятся в `internal/expedition_run.json`.

HTML-просмотрщик показывает истинную карту, наблюдения и результаты поиска. Модуль поиска получает сводный пакет наблюдений и справочники месторождений и пород.

Скважинные наблюдения можно читать из двух отдельных источников по `borehole_sources.json` либо из сводного пакета. Файлы сводного пакета и источников представляют одни и те же измерения: при объединении каждый результат учитывается один раз. Аналогично JSON и CSV внутри одного источника — два представления одинаковых записей.

Рельеф и геофизика дают по одной прибавке к приоритету. В JSON сохраняются идентификаторы проб, расчётные координаты интервалов и почвенный фон. Почвенная аномалия имеет только координаты в плане.

Магнитная карта показывает отклонения в обе стороны. Для поддержки железорудной цели используется положительное отклонение. Максимальное расстояние до измерения равно половине диагонали ячейки съёмки. Для гамма-признака наклонной скважины максимум составляет 5 м. Эти пороги заданы для прототипа. В результатах сохраняются измерение, фон, отклонение и связанная цель, когда есть подтверждение пробой и породой.

Для привязки цели к точке рельефа и обнажению используется половина диагонали ячейки полевой сетки. В `terrain_context` сохраняются тип рельефа, ближайшая точка съёмки, расстояние до неё и сведения о подходящем обнажении. Для наклонной скважины глубина под поверхностью оценивается как разность отметки ближайшей точки съёмки и отметки середины интервала. Глубина траншейной и вертикальной скважинной пробы берётся из измерений относительно местной поверхности. Порог 35 м принят для синтетического эксперимента. Для почвенных аномалий тип рельефа служит контекстом.

Пороги настроены для синтетического эксперимента. При пустой выдаче за пределами точек и интервалов наблюдений залежи всё ещё возможны.

### Восстановление пространственной карты

После выделения целей модуль `reconstruction.py` строит независимую сеточную карту. Он не принимает истинную карту и не использует её размеры по глубине, слои, идентификаторы залежей или их геометрию.

1. Горизонтальные размеры берутся из паспорта экспедиции. Вертикальные границы определяются отметками поверхности, устьев и забоев, а также глубиной траншей. Типичный размер ячейки равен 25 × 25 × 10 м. Для малых и крупных участков разрешение адаптируется автоматически.
2. Отметки рельефа, магнитные и гамма-измерения восстанавливаются раздельно взвешиванием по обратному квадрату расстояния до четырёх ближайших точек в пределах поискового радиуса.
3. Измеренные азимуты, наклоны, отметки устьев и интервалы журналов задают пересечения ячеек со скважинами. Траншеи и обнажения добавляют данные о породах у поверхности. Для остальных ячеек выбирается порода по взвешенным голосам ближайших независимых источников на том же высотном уровне. Литология вне области поддержки остаётся неизвестной.
4. Положительные анализы помещаются в ячейки по измеренной геометрии проб. Продолжение рудной зоны допускается только при наличии положительных анализов на двух независимых траекториях в пределах 2,5 горизонтальных шагов сетки, нахождении ячейки между двумя положительными участками (с допуском половины диагонали горизонтальной ячейки), достаточном взвешенном содержании и отсутствии более близкого отрицательного анализа. Неопределённые и забракованные пробы не считаются отрицательными измерениями. Одиночное пересечение остаётся локальной находкой.
5. Соседние рудные ячейки одного компонента и ячейки одного измеренного интервала группируются в пространственные зоны. Каждая зона содержит ссылки на цели и пробы, число наблюдаемых и интерполированных ячеек, границы сетки, максимальное измеренное содержание и дополнительные геологические признаки. В `mineral_deposit_estimates` зоны группируются по виду ископаемого: одна отдельная пространственно связанная зона соответствует одной предполагаемой залежи. Отдельно указывается, сколько зон опирается на один и сколько на несколько участков опробования. Это оценка числа залежей в восстановленной модели, а не фактическое число залежей на истинной карте.

Для каждой выделенной рудной зоны рассчитывается ориентировочный объём `V = n × dx × dy × dz`, где `n` — число ячеек зоны. Это объём блочной модели при допущении полного заполнения ячеек, а не измеренный объём залежи. Объёмы ячеек, пересекаемых положительными пробами, и интерполированных ячеек приводятся отдельно. Масса минерализованной породы равна `M = V × ρ`. Репрезентативная плотность `ρ` оценивается по незабракованным измерениям плотности керна в интервалах положительных проб (взвешивание по длине пересечения). При отсутствии таких измерений используются средние значения диапазонов плотности распознанных пород из справочника. Если плотность неизвестна, масса не рассчитывается.

В ячейках с положительными пробами содержание усредняется по длинам пересечений, а в интерполированных ячейках берётся из расчёта восстановления рудной зоны. Среднее содержание зоны — среднее по её ячейкам одинакового объёма при принятой постоянной плотности. Масса компонента равна массе породы, умноженной на массовую долю компонента. Для процентов доля равна содержанию, делённому на 100, для г/т — на миллион, для карат/т учитывается 0,2 г на карат. Для оксидов и составных аналитов рассчитывается масса именно указанного компонента (например, Li₂O, а не чистого лития). Значения `resources` сохраняются в каждой рудной зоне и суммируются в `mineral_deposit_estimates` по виду ископаемого; масса при недостающей плотности остаётся неизвестной. Итоги разных аналитов не складываются, поскольку их зоны могут пересекаться.

Сетка хранится в порядке `z_y_x`: индекс ячейки равен `(z * height_cells + y) * width_cells + x`. Отметка середины ячейки по вертикали равна `top_elevation_m - (z + 0.5) * depth_step_m`. В `lithology` хранится номер породы из `rock_catalog` (ноль означает неизвестную породу). Массив `lithology_support` отличает интерполяцию (1), пересечение наблюдения (2), отсутствие данных (0) и точки выше оценённой поверхности (-1).

В `mineral_zones` для каждой зоны сохраняются индексы ячеек и тип поддержки: 1 — интерполяция, 2 — положительная проба пересекает ячейку. Наличие такой ячейки не означает, что весь её объём минерализован. Сетка не предназначена для расчёта запасов. Границы интерполированных зон являются гипотезами, которые могут уточняться новыми наблюдениями.

`recognize.py` также сохраняет независимую карту рядом с результатом поиска. Другой путь можно задать параметром `--reconstructed-map`. Для открытия нового результата в общем просмотрщике при запуске `main.py` карта встраивается в HTML автоматически.
